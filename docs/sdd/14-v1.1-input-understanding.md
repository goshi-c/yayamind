# 14 V1.1 输入理解 SDD

## 背景

MVP 已经跑通自然语言写入任务、日程、提醒和执行记录的基础闭环。V1.1 需要把 AI 感优先放在输入理解上，让用户可以像跟小猫说话一样，把会议、提醒、任务、临时想法和准备事项自然说出来。

本阶段不是追求复杂对话 Agent，而是把一句话拆成更完整、可确认、可写入的数据。

## 用户场景

用户可能这样输入：

```text
明天下午 3 点跟同学开项目会，主要确认 V1.1 的输入理解，提前准备 TODO 和 SDD。
周五前提醒我把作品集截图整理一下。
这个会要记一下，目的就是确认下轮实现顺序。
今晚先把日期详情补好，可能要 1 个半小时。
```

小猫需要理解其中的时间、类型、标题、目的、准备事项、提醒、备注和预估时长，并在信息不完整时温和确认。

## 功能范围

V1.1 支持以下输入理解能力：

- 识别事项类型：会议、任务、提醒、临时想法、准备事项、执行记录。
- 提取时间字段：开始时间、结束时间、截止时间、相对提醒时间。
- 提取扩展字段：会议目的、准备事项、备注、预估时长、关联日期。
- 生成写入前结构化预览，让用户确认或修改。
- 对缺失关键信息提出 1 个短问题。
- 对低风险事项直接写入，对会影响安排的事项进入确认。

## 不做什么

- 不做长期闲聊记忆。
- 不让 AI 直接移动大量已有安排。
- 不做复杂多轮项目管理对话。
- 不把所有历史数据都发给模型。
- 不把 AI 候选结果绕过程序校验直接写入。

## 交互流程

```text
用户输入
  -> 规则解析明确时间和命令
  -> AI/规则生成结构化候选结果
  -> 程序校验时间、重复和冲突
  -> 小猫展示确认预览或追问一个关键问题
  -> 用户确认
  -> 写入 events/tasks/reminders/work_logs
  -> 一周安排和日期详情刷新
```

确认预览建议包含：

- 识别结果标题。
- 类型。
- 日期和时间。
- 目的/备注。
- 准备事项。
- 提醒。

## 数据结构变化

`events.jsonl` 建议扩展可选字段：

```json
{
  "purpose": "确认 V1.1 输入理解范围",
  "preparations": ["准备 TODO", "准备 SDD"],
  "notes": "下轮决定实现顺序",
  "reminderIds": ["reminder_xxx"],
  "sourceText": "用户原始输入"
}
```

`tasks.jsonl` 建议扩展可选字段：

```json
{
  "preparations": ["整理截图", "确认 README"],
  "notes": "作品集展示用",
  "estimatedMinutes": 90,
  "sourceText": "用户原始输入"
}
```

`reminders.jsonl` 建议保留关联字段：

```json
{
  "relatedType": "event",
  "relatedId": "event_xxx",
  "sourceText": "用户原始输入"
}
```

## API / 前后端影响

- `/api/input/parse` 返回更完整的 `fields`，包括 `purpose`、`preparations`、`notes`、`estimatedMinutes`、`reminders`。
- `/api/input/commit` 接收用户确认后的结构化结果，并写入对应数据文件。
- 前端小猫输入区需要展示结构化预览。
- 一周安排继续显示短标题，右侧日期详情显示完整字段。
- 后端继续采用规则优先、AI 兜底；没有 AI adapter 时可先用规则和 mock 结构跑通。

## 状态与异常

- 时间不明确：不直接写入日程，提示补充时间或先记为待定。
- 类型不确定：展示候选类型，让用户确认。
- 冲突或疑似重复：进入确认，不覆盖已有安排。
- AI 返回字段不完整：保留原文，生成短问题。
- 解析失败：小猫提示“我先把原话记下来，等你补一点时间/类型”。

## 验收标准

- 用户输入一段自然语言后，可以看到结构化确认预览。
- 会议能提取目的、准备事项和备注。
- 任务能提取截止时间、预估时长和准备事项。
- 提醒能关联到对应日程或任务。
- 信息不完整时只追问最关键的一个问题。
- 确认写入后，右侧日期详情能展示完整信息。
