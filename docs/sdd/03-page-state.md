# 03 页面状态 SDD

## 目标

页面状态用于描述个人助手当前处在什么工作语境里。它不是单纯的 loading / error 状态，而是连接小猫浮窗、今日面板、日历视图、输入确认和提醒行为的基础状态。

第一版先把状态逻辑定清楚，避免后续做页面、小猫交互、提醒和复盘时各自为政。

## 状态分层

页面状态分为两层：

```text
sessionState：当前执行状态
interactionState：当前交互状态
```

这样设计是为了避免状态互相打架。例如用户正在工作时，提醒也可能到来；此时当前执行状态仍然是工作中，只是交互层出现了提醒。

## sessionState

### idle

空闲陪伴状态。

适用情况：

- 页面刚打开，还没有正在执行的任务。
- 用户已经结束当前工作。
- 当前没有需要继续计时的事项。

页面表现：

- 小猫保持陪伴状态，可以冒出轻量提示。
- 右侧今日面板显示今天计划、待开始任务、未处理提醒。
- 输入区可以接收文字或语音。

### working

工作中状态。

适用情况：

- 用户点击开始工作。
- 用户说“开始写方案”“我现在开始做这个任务”。
- 系统已经确认当前工作事项。

页面表现：

- 右侧今日面板显示当前正在做的任务或时间块。
- 工作记录开始计时。
- 小猫可以轻量陪伴，但不频繁打扰。
- 如果有提醒到来，不强行打断当前工作。

### paused

暂停中状态。

适用情况：

- 用户说“暂停一下”“我去吃饭”“先停一下”。
- 当前工作没有结束，只是暂时中断。

页面表现：

- 当前工作保留。
- 工作计时暂停。
- 今日时间线记录一次 pause。
- 用户可以继续、结束、或记录暂停原因。

### reviewing

复盘中状态。

适用情况：

- 用户主动说“复盘一下”。
- 任务结束但没有完成。
- 系统检测到计划偏差，需要记录原因。

页面表现：

- 小猫不需要明显切换氛围，仍保持整体一致的陪伴感。
- 语气可以比平时更认真一些，但不变成严厉审问。
- 重点是问清楚原因、记录经验、帮助下次估时和安排更贴合真实情况。

## interactionState

### none

没有额外交互。

适用情况：

- 页面处于稳定展示状态。
- 用户没有正在确认、输入、处理提醒或选择方案。

### planning

计划整理状态。

适用情况：

- 用户正在添加任务、日程、时间块或生活事项。
- 系统正在把用户输入解析为结构化记录。

页面表现：

- 小猫可以展示正在理解或整理的反馈。
- 如果输入足够清楚且无冲突，可以直接记录。
- 如果信息不足或有冲突，转入 confirming。

### confirming

等待确认状态。

适用情况：

- 语音识别后需要用户确认文本。
- 时间不明确，例如“明天上午开会”。
- 疑似重复。
- 与已有安排冲突。
- 动态重排会移动已有计划。

页面表现：

- 给出一个明确问题或 1-2 个可选方案。
- 避免一次给太多选择。
- 用户确认后再写入数据或执行重排。

### reminding

提醒触发状态。

适用情况：

- 到达某个生活提醒、工作提醒或日程提醒时间。

页面表现：

- 不强行打断当前工作。
- 小猫可以冒泡轻提示。
- 如果浏览器通知权限可用，可以发浏览器通知。
- 用户未处理时，提醒安静挂在右侧今日面板里。

## 常见状态流

### 页面打开

```text
sessionState = idle
interactionState = none
```

小猫展示轻量陪伴提示，今日面板展示当天计划和待处理事项。

### 开始工作

```text
用户输入：开始写产品方案
sessionState = working
interactionState = none
```

系统记录当前工作，写入一条工作开始记录，今日面板显示当前任务。

### 暂停工作

```text
用户输入：暂停一下
sessionState = paused
interactionState = none
```

系统暂停当前计时，保留当前工作上下文。

### 添加时间不明确的日程

```text
用户输入：明天上午开会
sessionState = 保持不变
interactionState = confirming
```

系统不直接写入，而是询问大概几点或是否需要设为上午待定事项。

### 工作中来了提醒

```text
sessionState = working
interactionState = reminding
```

提醒不强打断当前工作。小猫轻提示，未处理提醒进入右侧今日面板。

### 任务没完成

```text
sessionState = reviewing
interactionState = confirming
```

系统询问没完成原因，记录复盘信息。语气认真但不明显切换人格或氛围。

## 写入数据的关系

页面状态本身不等于业务数据，但会触发业务数据写入。

常见写入：

- `working`：写入工作开始记录。
- `paused`：写入暂停记录。
- `reviewing`：写入复盘记录。
- `confirming`：确认后再写入任务、日程、提醒或重排结果。
- `reminding`：提醒触发和处理状态可写入提醒相关字段。

具体字段以后在 `01-data-schema.md` 中定义。

## 第一版不做

- 不做复杂状态机可视化。
- 不做多任务并行执行状态。
- 不做系统级强提醒。
- 不做复盘时明显换人格或大幅改变界面氛围。
- 不做自动看屏幕后切换状态。

## 验收标准

- 页面能区分空闲、工作中、暂停中、复盘中。
- 页面能在执行状态不变的情况下处理确认和提醒。
- 工作中触发提醒时，不会打断当前工作。
- 未处理提醒能留在右侧今日面板。
- 任务未完成时能进入复盘流程，并记录原因。
- 后续日历、今日面板、小猫浮窗、输入解析文档可以引用这套状态定义。
