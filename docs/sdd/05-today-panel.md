# 05 今日面板 SDD

## 目标

今日面板是 Web 面板右侧区域，用来承接当天最需要行动的信息。它不是完整数据中心，而是用户今天执行计划时最常看的工作台。

第一版重点展示：

- 当前工作状态。
- 今日计划。
- 今日执行时间线。
- 未处理提醒。
- 小猫建议。

## 核心区域

今日面板从上到下建议分为五块：

```text
当前状态
今日计划
执行记录
未处理提醒
小猫建议
```

这些区域可以在视觉上分组，但不要做成过重的层层卡片。

## 当前状态

当前状态读取 `03-page-state.md` 的 `sessionState`。

### idle

展示：

- 当前没有正在执行的任务。
- 今日下一个建议开始的任务或时间块。
- 可以提供“开始”入口。

### working

展示：

- 当前正在做什么。
- 已进行多久。
- 关联任务或日程。
- 暂停、结束、记录进度入口。

### paused

展示：

- 当前暂停的任务。
- 暂停时长。
- 继续、结束、记录原因入口。

### reviewing

展示：

- 当前复盘对象。
- 简短原因输入或选项。
- 复盘语气保持认真但不明显切换氛围。

## 今日计划

今日计划聚合当天相关数据：

- 今日 `events.jsonl` 中的日程和时间块。
- 今日到期的 `tasks.jsonl` 任务。
- 今日待触发的 `reminders.jsonl` 提醒。

排序建议：

```text
正在进行 > 即将开始 > 未完成 > 稍后事项 > 已完成
```

展示时要区分：

- 已安排到具体时间的事项。
- 今天要做但还没安排时间的任务。
- 已延期或有风险的事项。

## 执行记录

执行记录来自 `work_logs.jsonl`。

第一版显示今天的关键节点：

- 开始工作。
- 暂停。
- 继续。
- 记录进度。
- 结束。
- 被打断。

展示目标不是流水账堆满，而是让用户和复盘时能看见真实执行过程。

示例：

```text
20:00 开始写产品方案
20:45 记录进度：完成大纲
21:10 暂停：吃饭
21:40 继续
```

## 未处理提醒

未处理提醒来自 `reminders.jsonl`。

规则：

- 工作中提醒不强打断。
- 到点后小猫可以轻提示。
- 用户没有处理时，提醒安静挂在今日面板。
- 今日面板中显示 `pending`、`triggered`、`missed` 中仍需处理的提醒。

提醒可以提供：

- 标记完成。
- 稍后提醒。
- 忽略。

第一版可以先做状态设计，不必实现复杂稍后提醒策略。

## 小猫建议

小猫建议用于给用户轻量行动提示，不做复杂自动决策。

建议来源：

- 当前页面状态。
- 今日剩余计划。
- 未完成任务。
- 提醒状态。
- 简单冲突或过载判断。

建议风格：

- 日常保持陪伴感。
- 复盘时更认真一些。
- 不一次给太多选项。
- 默认只给一个主建议，必要时给 1-2 个方案。

示例：

```text
现在离下一个安排还有 40 分钟，可以先推进产品方案的大纲。
```

## 与其他模块的关系

今日面板是多个模块的汇总展示：

- 数据结构见 `01-data-schema.md`。
- 输入导致的状态变化见 `02-input-parser.md`。
- 当前页面状态见 `03-page-state.md`。
- 日历中的当天事项和今日面板使用同一份事件数据。
- 冲突和重排建议由 `06-conflict-reschedule.md` 产生，今日面板负责展示和让用户确认。

## 第一版不做

- 不做复杂统计图表。
- 不做完整项目管理面板。
- 不做多天详细复盘。
- 不做强打断式提醒。
- 不做大量 AI 长文建议。
- 不做多任务并行计时。

## 验收标准

- 能展示当前执行状态。
- 能展示今日已安排事项和未安排任务。
- 能展示今天的工作记录时间线。
- 未处理提醒能安静挂在面板里。
- 小猫建议能根据当前状态给出轻量提示。
- 今日面板能和日历视图、页面状态共享同一套数据理解。
