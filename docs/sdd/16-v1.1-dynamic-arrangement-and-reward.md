# 16 V1.1 动态安排与奖励反馈 SDD

## 背景

MVP 已经具备轻量冲突检测、过载提示和提醒处理。V1.1 不扩展为复杂自动排程，而是在用户输入和执行过程中提供更顺手的轻量动态安排，并让小猫用陪伴式反馈增强继续使用的动力。

小猫是陪伴型助手，不是严厉监督型助手。

## 用户场景

用户可能遇到：

- 临时插入一个会议，需要知道是否影响今天安排。
- 任务可能做不完，希望小猫给一个轻量调整建议。
- 完成一个准备事项，希望收到简短正反馈。
- 推进了一半，希望记录执行进度。
- 今天安排有点满，希望小猫不要继续强塞任务。

## 功能范围

V1.1 支持：

- 对新事项做轻量冲突和过载判断。
- 当时间不够时给 1-2 个调整建议。
- 对任务完成、提醒完成、进度推进给陪伴式反馈。
- 对未完成或延期保持温和语气，引导记录原因。
- 把执行记录继续沉淀到 `work_logs.jsonl` 和 `reviews.jsonl`。

反馈类型：

- 完成反馈：确认用户已经推进。
- 进度反馈：鼓励继续或建议拆小。
- 过载反馈：提醒时间不足，给轻量方案。
- 延期反馈：不责备，记录原因并建议下一步。

## 不做什么

- 不做复杂自动排程算法。
- 不做积分、等级、连续打卡等强游戏化系统。
- 不做严厉监督、惩罚或焦虑型提醒。
- 不自动移动重要会议或固定生活安排。
- 不给过多方案增加决策负担。

## 交互流程

```text
用户新增/更新事项
  -> 程序判断冲突、重复、过载
  -> 无风险则写入并给轻量反馈
  -> 有风险则给 1-2 个方案
  -> 用户选择
  -> 写入数据并刷新一周安排/日期详情
```

执行反馈流程：

```text
用户记录完成/进度/做不完
  -> 写入 work_logs
  -> 必要时写入 reviews
  -> 小猫给短反馈
  -> 日期详情展示执行记录
```

## 数据结构变化

`work_logs.jsonl` 可继续承接执行反馈，建议补充可选字段：

```json
{
  "mood": "steady",
  "feedbackType": "progress",
  "relatedType": "task",
  "relatedId": "task_xxx"
}
```

`reviews.jsonl` 可承接未完成原因：

```json
{
  "reasonType": "underestimated_time",
  "nextSuggestion": "下次先拆成 45 分钟的小块"
}
```

不需要新增复杂奖励数据表。V1.1 的奖励反馈先以即时文案和执行记录为主。

## API / 前后端影响

- 输入提交后继续走冲突和过载判断。
- `/api/input/commit` 或冲突处理接口返回 `feedback` 字段。
- 前端小猫气泡展示短反馈。
- 日期详情展示执行记录和未完成原因。
- 后端不需要引入复杂排程引擎，只在已有规则基础上增强文案和返回结构。

## 状态与异常

- 冲突事项：不直接覆盖，进入确认。
- 今日过载：提示时间不足，建议拆分或延期。
- 用户选择延期：更新任务或日程日期，并记录原因。
- 用户不想处理：允许先记为待定，不继续追问。
- 反馈生成失败：使用默认短文案，不影响写入。

## 验收标准

- 新事项冲突或过载时，小猫能给 1-2 个轻量方案。
- 完成任务或提醒后，小猫给简短陪伴式反馈。
- 做不完时，小猫引导记录原因，但不使用责备语气。
- 执行记录能出现在右侧日期详情中。
- 不引入复杂自动排程和强游戏化系统。
