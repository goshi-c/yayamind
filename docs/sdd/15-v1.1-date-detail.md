# 15 V1.1 日期详情 SDD

## 背景

MVP 已经实现点击一周安排中的某一天，在右侧展示该日期详情。V1.1 需要把右侧从“事项列表”增强为“选中日期的完整上下文”，让用户看到这一天每个安排为什么存在、要准备什么、有什么提醒、执行得怎么样。

首页第一屏仍然保持一周安排：左侧/中间是一周预览，右侧是选中日期详情。

## 用户场景

用户点击周三后，希望看到：

- 当天有哪些会议、任务、提醒。
- 某个会议的目的是什么。
- 开会前要准备哪些材料。
- 哪些提醒和这件事相关。
- 当天已经执行了哪些记录。
- 有哪些备注或临时想法。

## 功能范围

右侧日期详情在 V1.1 展示：

- 日期标题和当天概览。
- 当天日程和时间块。
- 会议目的。
- 准备事项。
- 关联提醒。
- 备注。
- 执行记录。
- 待定事项或未安排任务。

展示原则：

- 一周安排中仍显示短标题，避免第一屏拥挤。
- 完整信息放在右侧日期详情。
- 重点是可读和可行动，不做复杂数据中心。

## 不做什么

- 不做完整项目管理详情页。
- 不做复杂甘特图或多维统计。
- 不把右侧变成聊天记录堆叠区。
- 不做跨周长期复盘页面。
- 不做大量嵌套卡片。

## 交互流程

```text
用户点击一周安排中的日期或事项
  -> selectedDate 更新
  -> 右侧加载该日期 events/tasks/reminders/work_logs
  -> 按时间和状态聚合展示
  -> 点击单个事项可展开目的、准备事项、备注和提醒
```

右侧详情建议分区：

```text
日期概览
当日安排
待准备
提醒
执行记录
备注
```

如果用户点击具体事项，右侧可以优先展开该事项；如果只点击日期，则按当天整体展示。

## 数据结构变化

日期详情主要读取已有数据，并承接 V1.1 输入理解新增字段：

- `events.jsonl`
  - `purpose`
  - `preparations`
  - `notes`
  - `reminderIds`
  - `sourceText`
- `tasks.jsonl`
  - `preparations`
  - `notes`
  - `estimatedMinutes`
  - `sourceText`
- `reminders.jsonl`
  - `relatedType`
  - `relatedId`
- `work_logs.jsonl`
  - 继续用于当天执行记录。

## API / 前后端影响

- `/api/bootstrap` 或日期详情接口需要返回选中日期的完整聚合数据。
- 日历列表可以继续返回轻量事项，右侧详情请求或本地聚合完整字段。
- 前端状态需要保留 `selectedDate` 和可选的 `selectedItemId`。
- 右侧详情组件需要支持空状态、加载状态、冲突/待确认状态。

## 状态与异常

- 当天无安排：显示安静空状态，不催促用户。
- 有待定事项：放在当日安排顶部或单独区域。
- 有提醒未处理：显示完成、稍后、忽略入口。
- 有执行记录但无关联任务：按时间展示，不强行归类。
- 字段为空：隐藏对应小节，不显示空标题。
- 数据解析异常：保留原文或短标题，避免详情面板空白。

## 验收标准

- 点击任意日期后，右侧展示该日期完整详情。
- 会议事项能展示目的、准备事项、提醒和备注。
- 任务事项能展示预估时长、准备事项和执行状态。
- 今日详情能展示未处理提醒和执行记录。
- 一周安排仍保持短标题和高信息密度。
- 空状态温和，不出现严厉督促文案。
