# 00 产品范围 SDD

## 目标

本文件用于收束第一版 Web 模拟个人助手的产品范围，明确做什么、不做什么，以及各 SDD 模块之间的关系。

第一版目标不是做一个完整商业化日历或 TODO 工具，而是验证核心闭环：

```text
计划安排 -> 真实执行记录 -> 动态调整 -> 复盘沉淀 -> 下一次计划更贴合自己
```

## 产品定位

这是一个偏个人使用的 AI 个人助手。

它的差异点不是“能列任务”，而是：

- 用小猫浮窗作为陪伴型入口。
- 用 Web 面板展示计划和执行状态。
- 记录真实执行过程，而不只是计划。
- 在任务做不完或计划冲突时，给轻量重排建议。
- 通过复盘记录沉淀个人习惯和估时经验。
- 数据优先存到 Obsidian 本地文件。

## 第一版核心体验

第一版需要让用户完成这些场景：

- 打开 Web 面板，看到未来 7 天计划和今天状态。
- 通过文字或语音告诉小猫要添加任务、日程、提醒。
- 开始、暂停、继续、结束一项工作。
- 中途记录进度，例如“我可能写不完了”。
- 出现冲突或时间不明确时，由小猫简短确认。
- 任务没完成时，记录原因和经验。
- 到提醒时间时，小猫轻提示，未处理提醒挂在今日面板。

## MVP 范围

第一版包含：

- 三栏 Web 面板。
- 中间 7 天日历列视图。
- 右侧今日执行面板。
- 页面内小猫浮窗。
- 文字输入。
- 浏览器语音识别后的文本确认。
- 本地 JSON/JSONL 数据存储。
- AI 自然语言解析候选结果。
- 基础冲突检测和轻量重排。
- 浏览器内提醒。
- 复盘原因记录。
- 个人画像雏形的数据基础。

## 暂不做

第一版明确不做：

- 真正桌面应用。
- 系统托盘、置顶透明窗口、全局快捷键。
- 手机 App。
- 微信入口或小程序。
- 自动看屏幕或截图分析。
- 系统级常驻提醒。
- 外部日历同步。
- 多用户账号。
- 复杂自动排程算法。
- 长期全量聊天记忆。
- 特别精致的小猫动画。

这些能力可以作为后续阶段，但不进入 Web 模拟版 MVP。

## 模块关系

当前 SDD 模块：

```text
00-product-scope.md
01-data-schema.md
02-input-parser.md
03-page-state.md
04-calendar-view.md
05-today-panel.md
06-conflict-reschedule.md
07-cat-widget.md
08-reminders.md
09-ai-strategy.md
```

关系说明：

- `00-product-scope.md` 定义边界。
- `01-data-schema.md` 定义本地数据如何存。
- `02-input-parser.md` 定义用户输入如何变成结构化意图。
- `03-page-state.md` 定义页面和交互状态。
- `04-calendar-view.md` 定义中间日历如何展示。
- `05-today-panel.md` 定义右侧今日工作台。
- `06-conflict-reschedule.md` 定义冲突和重排边界。
- `07-cat-widget.md` 定义小猫入口和交互。
- `08-reminders.md` 定义提醒行为。
- `09-ai-strategy.md` 定义 AI 使用边界。

## 第一版成功标准

第一版可以算成功，如果它能做到：

- 用户能把任务、日程、提醒自然地记进去。
- 页面能清楚展示未来几天和今天的安排。
- 用户能记录自己真实工作过程。
- 工作中提醒不会强打断。
- 有冲突时不会静默覆盖已有计划。
- 做不完时能记录原因，而不是只把任务延期。
- 数据能以本地文件形式留在 Obsidian 中。

## 后续阶段

### 阶段 2：桌面壳

将成熟的小猫交互迁移到 Electron 或 Tauri，支持桌面常驻、窗口置顶、快捷键和系统通知。

### 阶段 3：更深系统能力

增加活跃窗口检测、空闲检测、可选截图分析、更完整的动态排程和个人画像。

## 第一版不做

本文件已在“暂不做”中定义第一版排除项。后续模块如果出现和这里冲突的能力，以本文件为准。

## 验收标准

- MVP 范围清楚，不把后续桌面能力提前塞进第一版。
- 所有 SDD 模块都能对应到第一版核心体验。
- 数据、输入、页面、提醒、AI 的职责边界清楚。
- 后续实现时不需要重新讨论“第一版到底做不做某能力”。
