# 13 实施路线 SDD

## 目标

实施路线用于把当前 SDD 转成可执行的代码开发顺序。第一版优先跑通主链路，再补体验细节。

主链路：

```text
本地数据文件 -> 本地 API -> Web 面板 -> 小猫输入 -> 写入数据 -> 页面刷新
```

## 开发阶段

### 阶段 1：项目脚手架

目标：

- 创建前端和本地后端基础结构。
- 跑通开发服务。
- 准备 TypeScript 类型和基础目录。

建议内容：

- React + TypeScript + Vite 前端。
- Node.js + Fastify 本地后端。
- 基础 `.env` 或配置文件。
- 前后端本地开发命令。

### 阶段 2：本地数据层

目标：

- 根据 `01-data-schema.md` 读写 JSON/JSONL。
- 自动创建数据目录和基础文件。
- 提供统一 repository/helper。

优先实现：

- `events.jsonl`
- `tasks.jsonl`
- `work_logs.jsonl`
- `reminders.jsonl`
- `settings.json`

### 阶段 3：本地 API

目标：

- 按 `12-local-api-contract.md` 提供前端可用接口。

优先实现：

- `GET /api/bootstrap`
- `GET /api/calendar`
- `GET /api/today`
- `POST /api/input/parse`
- `POST /api/input/commit`
- 工作状态接口
- 提醒状态接口

### 阶段 4：Web 面板骨架

目标：

- 实现三栏布局。
- 日历、今日面板、小猫浮窗都先能显示假数据或 API 数据。

优先实现：

- 左侧导航。
- 中间 7 天日历。
- 右侧今日面板。
- 小猫入口。

### 阶段 5：输入和写入闭环

目标：

- 用户通过小猫输入文字。
- 系统解析并写入本地文件。
- 页面刷新后能看到新任务、日程或提醒。

优先实现：

- 文字输入。
- 规则优先解析。
- 简单 AI adapter 占位。
- 确认流程。

### 阶段 6：执行记录与提醒

目标：

- 支持开始、暂停、继续、结束工作。
- 支持浏览器内提醒。
- 未处理提醒挂到今日面板。

优先实现：

- `work_logs.jsonl` 写入。
- 当前工作状态计算。
- 页面打开时检查提醒。
- 小猫气泡轻提示。

### 阶段 7：冲突检测和轻量重排

目标：

- 新时间块写入前检查冲突。
- 当天过载时给 1-2 个方案。
- 用户确认后再写入。

优先实现：

- 时间重叠。
- 疑似重复。
- 时间不明确。
- 简单过载判断。

## 开发顺序原则

- 先跑通数据闭环，再打磨 UI。
- 先实现文字输入，再接语音。
- 先规则解析，再接 AI。
- 先浏览器内提醒，再考虑系统级提醒。
- 先 Web 模拟版，再考虑桌面壳。

## 第一轮最小可运行版本

第一轮代码只需要做到：

- 页面能打开。
- 能读取本地演示数据。
- 能展示三栏布局。
- 能通过输入新增一个任务或提醒。
- 能写入 JSON/JSONL。
- 能刷新后看到刚写入的数据。

这比一开始追求完整 AI 和复杂重排更重要。

## 验收标准

- 开发者可以按阶段开始实现，不需要重新决定技术栈。
- 每个阶段都有明确产物。
- 第一轮最小可运行版本能验证本地数据闭环。
- 后续功能能自然接上 SDD 模块。
