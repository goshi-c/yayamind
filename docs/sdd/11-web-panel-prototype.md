# 11 Web 面板原型 SDD

## 目标

Web 面板原型用于定义第一版页面怎么组织信息。它不是营销首页，而是用户真正打开后就能使用的工作台。

第一版采用三栏布局：

```text
左侧导航 / 中间日历 / 右侧今日面板
```

小猫浮窗悬浮在页面之上，作为输入和轻量提醒入口。

## 页面结构

### 左侧导航

左侧用于长期维度入口。

第一版入口：

- 今日。
- 计划。
- 阶段性目标。
- 人物画像。
- 复盘。
- 设置。

第一版可以只做入口和占位，不要求每个页面都完整实现。

### 中间日历

中间是主要视图，展示未来 7 天列式日历。

要求：

- 每天一列。
- 从早到晚纵向展示。
- 今天有当前时间线。
- 过去时间置灰。
- 不同类型事项有颜色区分。
- 未安排任务不要伪装成已安排时间块。

细节见 `04-calendar-view.md`。

### 右侧今日面板

右侧承接今天最重要的信息。

内容：

- 当前工作状态。
- 今日计划。
- 执行记录。
- 未处理提醒。
- 小猫建议。

细节见 `05-today-panel.md`。

## 小猫浮窗位置

小猫默认放在右下角或右侧边缘。

规则：

- 不遮挡右侧面板核心内容。
- 可以拖动。
- 可以冒泡。
- 点击后打开输入面板。
- 有确认事项时，优先展示确认。

细节见 `07-cat-widget.md`。

## 第一屏优先级

用户打开页面后，第一眼要看到：

- 今天现在处于什么状态。
- 今天接下来要做什么。
- 未来几天大概有什么安排。
- 小猫入口在哪里。

不要把第一屏做成介绍项目的 landing page。

## 视觉方向

整体应该是轻量、温和、可长期使用的工作台。

建议：

- 信息密度适中。
- 避免大面积装饰性 hero。
- 颜色用于区分事项类型，不做花哨背景。
- 小猫可以可爱，但主面板仍要清晰可扫。
- 卡片和分区保持克制，不要卡片套卡片。

## 基础交互

第一版需要支持：

- 点击日历块查看详情。
- 点击今日任务开始工作。
- 在今日面板暂停、继续、结束工作。
- 通过小猫输入任务、日程、提醒。
- 出现冲突时展示确认方案。
- 提醒到点后进入小猫气泡和今日面板。

不要求第一版支持拖拽日历改期。

## 状态响应

页面要响应 `03-page-state.md` 中的状态：

- `idle`：展示今日计划和建议开始项。
- `working`：右侧突出当前工作。
- `paused`：保留当前任务并提示继续。
- `reviewing`：右侧或小猫承接复盘。
- `confirming`：展示确认问题或方案。
- `reminding`：提醒轻提示，未处理挂今日面板。

## 第一版不做

- 不做营销首页。
- 不做移动端复杂适配。
- 不做完整设置中心。
- 不做复杂数据图表。
- 不做日历拖拽排程。
- 不做小猫复杂动画。

## 验收标准

- 打开页面后直接进入可用工作台。
- 三栏信息层级清楚。
- 日历和今日面板能共享数据。
- 小猫浮窗可见且可作为输入入口。
- 当前工作、未处理提醒、冲突确认都有明确承接位置。
- 第一版页面足够支撑后续代码实现和作品集展示。
