# 06 冲突与重排 SDD

## 目标

冲突与重排负责判断新输入是否会影响已有计划，并在必要时给用户 1-2 个可选方案。

第一版原则是：

```text
无冲突直接记录，有冲突再确认；小事尽量自动，重要变化让用户拍板。
```

冲突判断由程序逻辑负责，AI 只辅助把方案表达得更自然。

## 直接记录的情况

以下情况可以直接写入数据：

- 新任务没有具体时间，只是加入待办。
- 生活提醒不影响已有计划，例如“20 分钟后提醒我晾衣服”。
- 新日程或时间块和已有安排不重叠。
- 记录进度、暂停、继续、结束工作等执行日志。
- 用户明确说“先记下来”“不用安排时间”。

直接记录后，小猫可以给轻量反馈，不需要再次追问。

## 需要确认的情况

以下情况进入 `interactionState = confirming`：

- 新日程或时间块与已有安排重叠。
- 新任务要安排到一个已经占用的时间段。
- 同一天相似标题、相似时间，疑似重复。
- 时间不明确，例如“明天上午开会”。
- 当天剩余可用时间明显小于任务预估时间。
- 重排方案会移动已有计划。
- 事项看起来重要，但缺少关键时间或截止信息。

确认问题要短，优先问最关键的一个点。

## 冲突类型

### time_overlap

时间重叠。

例子：

```text
已有：20:00-22:00 写方案
新增：21:00-22:00 训练
```

处理：

- 不直接覆盖已有安排。
- 给出保留原计划或调整其中一个的方案。

### duplicate

疑似重复。

例子：

```text
已有：明天 10:00 项目沟通会
新增：明天上午项目会
```

处理：

- 询问是同一件事还是新增事项。
- 如果是同一件事，更新原记录。
- 如果不是，创建新记录。

### overload

计划过载。

例子：

```text
今天剩余可安排时间约 1.5 小时
新增任务预计 3 小时
```

处理：

- 给 1-2 个拆分或延期方案。
- 不自动把任务塞满所有空隙。

### vague_time

时间不明确。

例子：

```text
明天上午开会
今晚写方案
```

处理：

- 如果可以先作为待定任务记录，就提供“先记为待定”。
- 如果必须安排日程，追问具体时间。

### move_existing

需要移动已有安排。

例子：

```text
用户说：把今晚写方案改到明早
但明早已有会议和训练
```

处理：

- 先展示影响。
- 用户确认后再移动。

## 重排方案规则

第一版只给 1-2 个方案。

方案要满足：

- 不移动用户没有确认要移动的重要事项。
- 尽量保留会议、训练、吃饭、休息等固定安排。
- 优先移动普通任务块，而不是固定日程。
- 如果任务过大，优先建议拆分。
- 如果当天过载，允许建议延期。

示例：

```text
今天还剩大约 1.5 小时，但这个任务预计要 3 小时。

方案 A：今晚先做 1 小时，明天上午继续。
方案 B：整体放到明天上午。
```

## AI 的角色

AI 可以参与：

- 判断用户输入的大概意图。
- 帮助生成更自然的解释文案。
- 把程序生成的候选方案说得更清楚。

AI 不负责：

- 最终判断是否冲突。
- 直接移动已有计划。
- 自行创建大量重排方案。
- 覆盖用户明确安排。

程序逻辑负责读取 `events.jsonl`、`tasks.jsonl`、`reminders.jsonl` 并判断时间、重复和过载。

## 与数据的关系

可能更新的数据：

- `events.jsonl`：新增、移动、取消或标记时间块。
- `tasks.jsonl`：更新任务状态、截止时间、关联时间块。
- `work_logs.jsonl`：记录用户执行过程中的偏差和进度。
- `reviews.jsonl`：记录没完成原因和经验。

重排被用户确认前，不写入正式数据。可以在页面中显示临时候选方案。

## 与页面状态的关系

冲突出现时：

```text
interactionState = confirming
```

如果用户正在工作：

```text
sessionState 保持 working
```

也就是说，确认弹层或小猫提问不应该让当前工作状态丢失。

## 第一版不做

- 不做复杂自动排程算法。
- 不做全天候智能优化。
- 不做多目标权重排序。
- 不做自动移动大量已有计划。
- 不做和外部日历的冲突合并。
- 不让 AI 直接决定最终排程。

## 验收标准

- 无冲突事项可以直接记录。
- 时间重叠、疑似重复、时间不明确会进入确认。
- 当天明显过载时，能给出 1-2 个轻量方案。
- 重排不会在用户确认前写入正式数据。
- 工作中发生冲突确认时，不会丢失当前工作状态。
- AI 只辅助表达，不承担最终排程判断。
