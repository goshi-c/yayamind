## 2. 产品概述与背景

YayaMind 是一个本地优先、语音优先、带陪伴感的个人执行助手。它用 Web 工作台承载一周安排、日期详情、项目待办、提醒、执行记录和总结，用桌面小猫提供更低成本的日常输入入口。

当前 MVP 要解决的问题不是做一个完整商业化日历系统，而是让用户能把课程、会议、项目任务、生活提醒和执行记录稳定写入本地数据，并在同一个工作台里查看、编辑、复盘。

MVP 的核心闭环：

```text
自然语言或手动输入 -> 解析 / 追问 / 确认 -> 写入本地数据 -> 工作台刷新 -> 用户能继续查看、编辑和复盘
```

## 3. 用户与场景分析

### 目标用户

- 主要用户：需要同时管理课程、项目、求职、生活安排的个人用户。
- 当前真实用户：本机使用者，优先保证日常入口稳定、数据可控、文档可交接。
- 次要目标：可作为 AI 产品经理作品集案例，但本文件不写成面试展示稿。

### 高频使用场景

| 场景 | 用户要完成什么 | 核心痛点 | MVP 要提供的能力 |
|---|---|---|---|
| 快速记录安排 | 对小猫或输入框说一句日程、任务、提醒 | 手动填表慢，AI 聊天不稳定落库 | 解析自然语言，缺信息追问，明确事项写入本地数据 |
| 查看今天和本周 | 扫视本周安排，点某天看完整信息 | 周视图适合扫视，不适合承载准备事项和执行记录 | 中间一周安排 + 右侧日期详情 |
| 管理项目待办 | 按工作、学校、生活等项目整理任务 | 日历不适合无固定时间的任务 | 项目待办分组、截止日期、完成态、月历点 |
| 桌面低成本输入 | 不打开浏览器也能说一句记录 | 开发预览和真实入口容易混淆 | 桌面小猫单击听写、双击打开、阶段收口真实入口验证 |
| 执行复盘 | 记录完成、延期、进度和原因 | 普通 TODO 只知道做没做 | 执行记录、总结、画像雏形 |

### 5.2 F-01 工作台初始化与一周安排

- 优先级：P0
- 用户目标：打开 Web 或桌面主窗口后，立即看到本周安排、待办入口和右侧日期详情。
- 触发条件：访问 Web 工作台、桌面主窗口启动、桌面小猫双击打开主窗口。
- 交互逻辑：默认展示当前自然周周一到周日；今天高亮；过去时间弱化；点击日期只切换右侧日期详情；点击事项才进入该事项详情。
- 业务流程：前端请求 `/api/bootstrap`，后端聚合本地数据，前端渲染周视图和右侧详情。
- 状态流转：加载中 -> 加载成功 / 加载失败；选中日期 -> 选中事项 -> 编辑态 / 查看态。
- 输入字段：无显式输入；依赖当前日期、用户设置和本地数据。
- 输出字段：`calendar`、`tasks`、`todoProjects`、`profile`、`settings`、提醒和总结数据。
- 数据读取位置：`personal-assistant-data/` 下的 `events.jsonl`、`tasks.jsonl`、`reminders.jsonl`、`work_logs.jsonl`、`settings.json` 等。
- 异常情况：API 未启动、数据文件损坏、空数据、真实入口加载旧静态资源。
- 验收标准：`/api/bootstrap` 返回 200；页面不是空白；周一到周日展示稳定；点击日期不误触编辑；右侧展示对应日期上下文。

### 5.3 F-02 自然语言输入解析与提交

- 优先级：P0
- 用户目标：用一句中文新增、修改、补充、删除日程或任务，并看到结果写入工作台。
- 触发条件：页面小猫输入、桌面小猫听写结束、确认卡片提交、追问补充。
- 交互逻辑：先 parse，只展示理解、追问或风险；只有 commit 才写入数据；写入后必须刷新工作台。语音转写后的 AI 纠错只修明显错别字和语义不通顺处，不得把长任务摘要成短标题；项目待办标题必须保留完整事项内容。
- 业务流程：

```text
用户文本 -> POST /api/input/parse -> 缺信息追问 / 风险确认 / 可提交预览 -> POST /api/input/commit -> 写入数据 -> GET /api/bootstrap -> 定位结果
```

- 状态流转：输入中 -> 解析中 -> 待确认 / 追问中 / 可自动提交 -> 写入中 -> 写入成功 / 写入失败。
- 输入字段：`text`、`source`、可选 `selectedOptionId`、追问补充文本。
- 输出字段：解析结果、意图类型、标题、时间、准备事项、风险提示、写入结果、用户反馈文案。
- 数据写入位置：`events.jsonl`、`tasks.jsonl`、`reminders.jsonl`、`work_logs.jsonl`。
- 异常情况：AI key 缺失、AI 返回不可用、AI 纠错吞内容、项目名同音误识别、时间缺失、冲突、重复、过载、写入失败、commit 成功但前端未刷新。
- 验收标准：`/api/input/parse` 不写文件；`/api/input/commit` 才写文件；明确日程能写入并刷新；长语音待办不被压缩成两三个字；缺时间不静默误写；失败不展示成功态。

### 5.4 F-03 桌面小猫语音入口

- 优先级：P0
- 用户目标：桌面上单击小猫说一句安排，系统听写、解析、写入或追问。
- 触发条件：桌面小猫单击开始听写，再次单击停止并提交；双击只打开主工作台；拖动只移动位置。
- 交互逻辑：桌面小猫通过 Electron IPC 通知主工作台；当前路线使用 Windows 系统听写桥接收文本；无需确认且无冲突时可自动提交；需要确认时保留追问；从听写结束到 parse、commit、refresh 完成前，小猫保持处理中状态，不提前进入睡觉状态；听写中显示动态光圈，安排事项中改为静态站立 / 坐着状态，不继续闪听写光圈；悬浮窗透明区域不应拦截后方网页或文档点击，只有小猫本体区域可点击和拖动；气泡右侧提供取消按钮，点击后关闭当前语音状态并舍弃本次对话内容。
- 业务流程：

```text
单击小猫 -> native voice start -> 隐藏输入接收听写 -> native voice stop -> parse -> auto commit 或追问 -> bubble 反馈 -> refresh
```

- 状态流转：休息中 -> 听写中 -> 文字整理中 -> 理解意图中 -> 安排事项中 -> 待确认 / 写入成功 / 写入失败 -> 完成后短暂停留再休息。
- 输入字段：系统听写文本、来源 `voice`、桌面 IPC 事件。
- 输出字段：小猫状态、气泡反馈、结构化日志、写入结果。
- 数据写入位置：同 F-02；桌面运行态数据优先确认 `D:\YayaMindData\personal-assistant-data\`。
- 日志位置：`D:\YayaMindData\userData\desktop-cat.log`。
- 异常情况：点击未到 IPC、听写无文本、parse 成功但未 commit、真实入口仍是旧包、API 未启动。
- 验收标准：日志出现 `native-voice-stop`、`desktop-recognized-text`、`desktop-auto-commit-start`、`commit-success`；日程或任务刷新可见；解析/写入期间小猫不睡觉，用户能同时看到原输入和灰色阶段提示（文字整理中 / 理解意图中 / 安排事项中 / 完成了），处理中气泡不自动消失；取消按钮能舍弃当前语音会话且不写入；拖动不触发点击；双击不开始听写；把小猫放在文档或网页上时，小猫周围透明区域可以点透到底层应用。

### 5.5 F-04 右侧日期详情查看与编辑

- 优先级：P0
- 用户目标：点某一天查看完整安排，单击某条事项只选中 / 查看，双击某条事项后进入编辑；右键某条事项可快速删除。
- 触发条件：点击周视图日期、点击日程块、点击项目待办 deadline 日期、点击右侧编辑入口。
- 交互逻辑：中间周视图负责扫视和选择；右侧详情承载完整内容和编辑；当天标题今天只显示“今天”；一周详情不使用横向分割线，日程区和待办区各自滚动且隐藏可拖动滚动条；待办区略向下留白，只显示两部分：第一行截止时间，后续直接完整显示待办内容，不显示项目分类、具体安排标签或备注标签；查看态字号更小、允许换行，软删除后立即从 UI 移除。
- 业务流程：选择日期 -> 聚合当天日程、任务、提醒、执行记录 -> PATCH / DELETE -> 刷新。
- 状态流转：查看态 -> 编辑态 -> 保存中 -> 保存成功 / 保存失败；删除中 -> 已取消。
- 输入字段：标题、日期、开始时间、结束时间、准备事项、备注、任务状态、deadline、执行记录内容；待办和详情编辑框高度按换行与长句折行动态估算，不能固定两行，编辑态字体、行高与预览态一致。
- 输出字段：更新后的事项、右侧详情列表、日历块位置。
- 数据写入位置：`events.jsonl`、`tasks.jsonl`、`work_logs.jsonl`。
- 异常情况：编辑后未刷新、软删除记录继续参与冲突、点击日期误进编辑、乐观更新失败。
- 验收标准：点击日期只选中日期；单击事项只进入查看 / 选中态；双击事项才进入编辑态；编辑框无额外保存按钮，点击外部自动保存；右键事项只弹出“删除”菜单，事项本身用虚线框标明删除范围；确认删除后不展示、不参与冲突；待办编辑框按内容行数和长句折行自然展开，编辑前后排版一致。

### 5.6 F-05 项目待办

- 优先级：P0
- 用户目标：按项目管理没有固定时间的任务，给任务设置截止日期和完成状态。
- 触发条件：进入待办导航、新增任务、新增项目、拖到其他项目、拖到月历日期、完成或删除任务。
- 交互逻辑：左侧按项目分组；完成任务下沉和弱化；deadline 以日期 tag 和月历色点展示；项目名和待办标题都必须双击才进入编辑；普通悬停保持箭头光标，只有长按进入拖拽武装态才显示抓取光标，进入编辑框后才显示文本插入光标；右键具体待办或项目空白区域时，只在鼠标旁弹出只含“删除”的菜单，当前删除范围由待办或项目卡片上的虚线框表达，虚线框范围与拖拽选中范围一致；用户不想删除时点击页面其他位置使菜单失焦关闭；删除项目时项目内待办迁移到未归类；未归类是唯一兜底收纳区，不作为普通项目删除，也不允许历史同名项目继续冒充普通项目；AI / 规则识别项目待办时必须优先匹配已有项目词表，语音同音或近似转写也尽量回到已有项目；只有具体时间点的任务才进入日期详情。
- 业务流程：前端操作 -> `/api/tasks` 或 `/api/todo-projects` -> 写入任务 / 项目文件 -> 刷新项目分组和月历点。
- 状态流转：todo -> in_progress / done / cancelled；未分类 -> 项目归属；无 deadline -> 有 `dueAt`。
- 输入字段：任务标题、备注、项目 ID、deadline、状态、估时、准备事项。
- 输出字段：任务列表、项目分组、月历色点、右侧截止任务。
- 数据写入位置：`tasks.jsonl`、`todo_projects.json`。
- 异常情况：项目删除后任务丢失、完成态不刷新、deadline 只前端显示未写入、普通待办挤占日程详情、AI 识别出不存在的项目名时误新建项目。
- 验收标准：新增、编辑、完成、删除、移动和设置 deadline 后刷新仍一致；手动新增待办标题非空时失焦自动保存；右键不会直接删除，必须先出现鼠标旁确认菜单；取消任务不再出现在开放列表；无法匹配到已有项目的语音/文本待办进入唯一未归类，不自动新建项目。

### 5.7 F-06 本地数据层与软删除

- 优先级：P0
- 用户目标：数据保存在用户可控位置，取消和删除可追踪，不误删真实数据。
- 触发条件：所有新增、编辑、删除、完成、提醒处理、总结生成。
- 交互逻辑：写入通过后端统一处理；前端不能绕过后端直接改文件；删除默认软删除或取消。
- 业务流程：API 校验 -> 读取文件 -> append 或 rewrite -> 返回结果 -> 前端刷新。
- 状态流转：scheduled / todo / active -> done / cancelled / dismissed 等。
- 输入字段：各数据对象字段见第 7 节。
- 输出字段：写入结果、ID、状态。
- 数据位置：开发态 `personal-assistant-data/`；真实桌面入口运行态 `D:\YayaMindData\personal-assistant-data\`。
- 异常情况：JSON/JSONL 解析失败、文件不存在、桌面和开发态数据目录混淆、卸载或清理误碰数据目录。
- 验收标准：数据文件自动初始化；软删除记录不展示、不参与冲突；正式入口验收时明确当前读写的数据目录。

### 5.8 F-07 冲突、重复、缺信息、过载处理

- 优先级：P1
- 用户目标：系统发现风险时少问、问准，不静默写错。
- 触发条件：时间不明确、时间重叠、疑似重复、当天计划过载、意图不确定。
- 交互逻辑：只给用户能理解的动作，例如修改、保留重叠、取消；不暴露内部枚举。
- 业务流程：parse 或 commit 前后执行规则守卫；需要确认时停止自动写入。
- 状态流转：解析中 -> 缺信息 / 冲突 / 重复 / 过载 -> 用户补充或选择 -> 重新 parse 或 commit。
- 输入字段：新事项字段、已有日程和任务、用户选择项。
- 输出字段：追问问题、风险提示、可选动作。
- 数据位置：读取 `events.jsonl`、`tasks.jsonl`，确认前不写入。
- 异常情况：显式时间仍被追问、取消记录继续参与冲突、日程按标题误判重复。
- 验收标准：缺时间只追问关键问题；真实时间重叠才提示冲突；用户未确认前不覆盖旧数据。

### 5.9 F-08 陪伴式反馈、提醒、执行记录

- 优先级：P1
- 用户目标：完成、延期、提醒处理后得到短而温和的反馈，并留下执行信号。
- 触发条件：任务完成、提醒 done / dismiss / snooze、工作 start / pause / resume / finish、延期或进度记录。
- 交互逻辑：小猫反馈短句不责备；到点提醒只在刚触发时冒泡；旧提醒不反复打扰。
- 业务流程：用户动作 -> API 写入提醒状态或工作日志 -> 前端刷新 -> 小猫反馈。
- 状态流转：提醒 pending -> done / dismissed / snoozed；工作 start -> pause / resume -> finish。
- 输入字段：提醒 ID、snooze 分钟、工作备注、任务 ID、完成原因。
- 输出字段：提醒状态、执行记录、反馈文案。
- 数据位置：`reminders.jsonl`、`work_logs.jsonl`。
- 异常情况：旧提醒重复冒泡、反馈挡住主任务、用户取消却被记录为失败。
- 验收标准：提醒处理状态可回溯；小猫默认低打扰；完成或延期能写入执行记录。

### 5.10 F-09 总结和个人画像雏形

- 优先级：P2
- 用户目标：把执行记录转成每日 / 每周总结，并初步沉淀个人习惯。
- 触发条件：用户点击生成总结、执行记录积累、设置变化。
- 交互逻辑：总结生成到 Markdown；画像只从执行信号沉淀，不硬造结论。
- 业务流程：读取日程、任务、执行记录、提醒 -> 生成 Markdown 或画像快照 -> 前端展示。
- 状态流转：未生成 -> 生成中 -> 已生成 / 失败。
- 输入字段：总结类型 `daily` / `weekly`，日期范围，执行数据。
- 输出字段：Markdown 总结、画像快照。
- 数据位置：`summaries/`、`profiles.json`、`work_logs.jsonl`、`tasks.jsonl`。
- 异常情况：总结内容凭空编造、文件写入失败、画像和实际记录不一致。
- 验收标准：能生成可读 Markdown；失败时提示明确；画像基于已有数据。

## 7. 数据需求

| 数据对象 / 文件 | 关键字段 | 读写边界 |
|---|---|---|
| `events.jsonl` | `id`、`title`、`date`、`startAt`、`endAt`、`type`、`status`、`preparations`、`notes` | 日程和时间块；新增和编辑写入；`cancelled` 不展示、不参与冲突 |
| `tasks.jsonl` | `id`、`title`、`projectId`、`dueAt`、`status`、`estimatedMinutes`、`preparations`、`notes` | 项目待办和截止任务；完成、取消、移动项目、设置 deadline 都写入 |
| `todo_projects.json` | `id`、`title`、`order`、`createdAt`、`updatedAt` | 项目待办分类；删除项目时任务应迁回未归类；未归类作为虚拟兜底区返回，不应被删除或重复新建 |
| `reminders.jsonl` | `id`、`title`、`dueAt`、`status`、`source`、`eventId` | 普通提醒和出门提醒；处理状态要可回溯 |
| `work_logs.jsonl` | `id`、`type`、`note`、`taskId`、`at` | 执行记录、进度、延期和完成原因 |
| `goals.json` | 目标标题、状态、目标日期 | 阶段目标页读取和写入 |
| `profiles.json` | 时间习惯、任务估时、生活节奏、工作偏好 | 从执行信号沉淀，不硬造结论 |
| `settings.json` | 起床 / 睡觉时间、休息日、城市、提醒偏好 | 时间轴固定 0:00-24:00；作息用于生成灰色“休息”块，并影响天气提醒、休息日展示 |
| `summaries/` | Markdown 文件 | 每日 / 每周总结输出，可放回 Obsidian |
| `desktop-cat.log` | 结构化事件 | 只用于诊断桌面小猫、IPC、语音和 commit 链路 |

## 8. 依赖与约束

- 云端能力：Vercel / Supabase 历史上已接入，但当前 MVP 收口主线以本地优先和桌面入口稳定为准。

### 2.0 规划

- 更完整的动态排程和个人画像。
- 可选的外部日历同步。
- 可选的 PWA / 移动端入口。
- 更深入的周报、月报和长期习惯分析。

### Not Now

- 不做多人账号协作。
- 不做微信、小程序或原生手机 App。
- 不做未经授权的屏幕感知、截图分析或后台监听。
- 不做复杂自动排程引擎替用户大规模移动安排。
- 不做全局语音唤醒常驻监听。
- 不迁移或删除真实用户数据目录。

## 11. 文档分工

- `PRD.md`：当前产品需求、优先级、状态、验收标准和版本规划。
- `SDD.md`：系统架构、模块设计、数据设计、接口设计、核心流程、状态机、测试和运维。
- `TODO.md`：当前版本任务拆解、完成状态和下一轮任务。
- `PROJECT_CONTEXT.md`：历史上下文、重要决策、验证结果、风险和旧链路回溯。
- `FILE_INDEX.md`：文件、目录、日志、数据和资源定位。
- `README.md`：外部展示和运行入口说明。
- `docs/interview/`、`docs/portfolio/`：面试和作品集材料，不作为日常开发依据。
